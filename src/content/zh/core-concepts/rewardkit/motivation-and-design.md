# 动机与设计 {#motivation-design}

> RewardKit 为何存在，以及其设计原则。

## 动机 {#motivation}

为 Harbor 创建新任务时，编写验证器往往是最繁琐的部分。我们查看了流行基准中的验证器实现，发现它们常常是复杂脚本，难以阅读、扩展，也难以跨任务复用。这导致任务之间复制粘贴样板代码，从而在评测中引入验证器的细微错误。

**RewardKit** 解决了这一问题。它将常见模式打包为可在任务间共享和复用的组件。RewardKit 通过支持 LLM 和 Agent 作为评判器的评估以及部分得分，消除了样板代码。由于独立的奖励组件通过目录结构定义，即使不阅读代码，验证器也能一目了然。并行且隔离地评估多项评判项是 RewardKit 的原生能力。

## 设计原则 {#design-principles}

* **简洁：** 验证器由目录结构定义，一眼即可读懂。常见评判项是单行调用。自定义逻辑是带装饰器的函数。评判器是可复用的 TOML 文件。
* **复用与共享：** 奖励评判项是目录中的普通文件。可以跨任务共享，并在 git 中进行版本管理。
* **零样板：** 20 余项内置评判项，覆盖文件、命令、JSON、CSV、HTTP、图像和轨迹。原生支持 LLM 和 Agent 作为评判器。
* **隔离：** 评判项可以在隔离的文件系统快照中运行，从而不会相互干扰或损坏 Agent 的工作区。
